# Behavior analytics audit — 2026-11-07

## What was in the repository

The first-party `RevolutionBehavior-L8-System` was already wired into the website through `frontend/src/lib/consent/init.ts`. Its browser tracker (`frontend/src/lib/behavior/tracker.ts`) sends batches to the SvelteKit proxy (`frontend/src/routes/api/behavior/events/+server.ts`), which forwards them to the Rust ingestion route (`api/src/routes/behavior.rs`) and PostgreSQL `behavior_events` table (`api/migrations/075_behavior_events.sql`). The Rust admin summary route and `/admin/behavior` dashboard were also present.

The two dedicated admin pages were incomplete. Heatmaps requested `/api/admin/analytics/heatmaps`, which the proxy forwarded to a Rust route that did not exist. Its visualization was a placeholder and its scroll percentages were constants. Recordings requested another nonexistent endpoint and displayed a placeholder player; no DOM recorder existed. The latter template included fields for raw user email even though the Rust ingestion route deliberately ignored user identity. The old client could leave full URL queries, referrers and form metadata in `localStorage` retry batches even though the server dropped them. A dormant module auto-initialized the tracker on import without consent. Retry storage and database events had no retention policy.

A separate public `/behavior` page called an orphan API client pointed at nonexistent `/admin/behavior/*` routes. The live admin navigation already used `/admin/behavior`.

## Changes made

| Layer      | Verified behavior                                                                                                                                                                                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capture    | Consent-driven start and stop; DNT/GPC checks; no DOM or form-value capture; sensitive controls and protected routes excluded; paths, safe element tags and normalized viewport click coordinates only; navigation page views; hidden-page flush; cryptographic random session identifiers.                   |
| Retry      | Client sanitizes before buffering and immediately rewrites older retry batches; consent withdrawal clears pending batches; the legacy persistent visitor ID is removed.                                                                                                                                       |
| API        | Bounded ingestion with validation and deduplication; private paths and unsafe selectors rejected or removed; admin-authenticated heatmap list/detail and paginated session list/detail endpoints.                                                                                                             |
| Storage    | Migration `119_behavior_retention_and_coordinates.sql` marks normalized coordinates, clears historical unsafe selectors and private paths, and indexes 90-day retention. A background worker deletes expired events in 1,000-row batches.                                                                     |
| Admin UI   | Heatmaps plot measured 5% viewport cells and scroll counts. The legacy `/admin/analytics/recordings` URL now shows an event timeline explicitly labeled **Session activity**. The dashboard uses real recent sessions and click counts instead of an empty recordings array and unrelated heatmap-view count. |
| Legacy URL | `/behavior` now redirects to `/admin/behavior` with HTTP 308; its unused page, API client and store were removed.                                                                                                                                                                                             |

The event timeline is intentionally not video or DOM replay. A recorder would require a separate consent, redaction and deletion design for page content and forms. Historical absolute click coordinates are excluded from the new normalized visualization; they remain available for other aggregate metrics until retention removes them.

## Remaining limits

- No production deployment, production traffic measurement, load test, or third-party security review is represented by these local results. No vendor-parity or “best in the world” claim is supported.
- The public Rust ingestion route accepts anonymous events. The website proxy checks request origin, but direct server-to-server traffic can still submit fabricated events. Distributed abuse controls and source attestation require deployment infrastructure and are separate from the feature correctness shown here.
- A path may itself contain a sensitive identifier outside the excluded route prefixes. The client and API strip queries and fragments, and reject email-like paths, but product route review is still needed as new private routes are added.
- The 90-day worker controls rows in `behavior_events`; database backups and downstream exports require their own retention policy.

The privacy boundary follows the [OWASP logging data-exclusion guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html). The hidden-page flush follows the [Chrome page lifecycle guidance](https://developer.chrome.com/docs/web-platform/page-lifecycle-api). GPC handling uses the browser's [globalPrivacyControl signal](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/globalPrivacyControl).
